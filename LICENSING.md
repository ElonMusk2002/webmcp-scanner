# Как выдавать Pro-лицензии (ручной v1, без бэкенда)

## Один раз, перед первым запуском
1. Создать публичный репозиторий на GitHub (например `webmcp-scanner-licenses`), закинуть туда `valid-keys.json` (сейчас `[]`).
2. Скопировать raw-ссылку на файл: `https://raw.githubusercontent.com/<username>/<repo>/main/valid-keys.json`.
3. Вставить эту ссылку вместо `<YOUR_GH_USERNAME>/<YOUR_REPO>` в `popup.js` → константа `LICENSE_LIST_URL`.
4. ✅ Готово: публичная payment-ссылка на $5 уже создана в NOWPayments — `https://nowpayments.io/payment/?iid=5936649146`. Она уже вшита в кнопку "Get Pro" в попапе расширения.

## На каждую продажу
1. Видите оплату в дашборде NOWPayments (Payments → Payments history).
2. Генерите случайный ключ, например: `openssl rand -hex 8` в терминале.
3. Добавляете этот ключ строкой в массив `valid-keys.json` на GitHub, коммитите.
4. Отправляете покупателю ключ на почту (тот email, что он указал при оплате в NOWPayments).

Важно: ссылка сейчас — разовый платёж на $5, не авто-подписка (настоящий Subscriptions-функционал
в NOWPayments требует заранее добавлять email каждого клиента вручную — не годится для публичного
поста). Значит "месячный" тариф на деле означает: через месяц вручную напоминаете клиенту продлить
той же ссылкой. Нормально для v1, авто-биллинг — уже когда будет понятен спрос.

## Как это проверяется в расширении
`popup.js` при активации делает `fetch` на raw-ссылку, без кэша, и просто проверяет `validKeys.includes(key)`.
Если список недоступен — считаем лицензию невалидной (fail closed), пользователь остаётся на free-тире.

## Когда автоматизировать
Как только продаж станет больше 5-10/месяц — вручную коммитить ключи станет неудобно.
Тогда: NOWPayments IPN (webhook) → Cloudflare Worker, который сам генерит ключ и коммитит
в `valid-keys.json` через GitHub API при успешном платеже. Не делаем это сейчас, пока
не подтверждён спрос — сначала продукт, потом автоматизация.
